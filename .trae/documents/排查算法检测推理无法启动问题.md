# 排查算法检测推理无法启动问题 — 实施计划

## 一、问题摘要

算法模型注册成功后，使用已注册模型进行检测推理测试及 UAV 原始图片检测时无法正常启动。
经 Phase 1 探索诊断，**根因已 100% 确认**：`device: 'auto'`（字符串）在 ultralytics 8.4.60 中
是无效值，`select_device('auto')` 始终抛出 `ValueError: Invalid CUDA 'device=auto' requested`，
导致所有检测/计数推理调用在 `engine.predict()` 阶段直接失败。

## 三、拟议修改

### 修改 1：后端 detector.py — device 值归一化 + GPU 降级（核心修复）

**文件**：`backend/core/detector.py`
**原因**：`device='auto'` 始终触发 ValueError；需归一化为 ultralytics 可接受的值，并在 GPU 推理
失败时自动降级到 CPU（应对 CUDA 间歇性不可用）。
**改动**：

```python
def detect(self, image, model_name=None, params=None, draw=True) -> dict:
    params = params or {}
    cfg = self.registry.get_config(model_name)
    imgsz = params.get("imgsz", cfg.get("imgsz", 640))
    conf = params.get("conf", cfg.get("conf", 0.5))
    iou = params.get("iou", cfg.get("iou", 0.3))
    max_det = params.get("max_det", cfg.get("max_det", 300))
    device = self._normalize_device(
        params.get("device", cfg.get("device"))
    )  # 归一化：'auto'/''/None → None；'cuda:0' → 0

    engine = self.registry.get_engine(model_name)
    try:
        results = engine.predict(
            image, imgsz=imgsz, conf=conf, iou=iou, max_det=max_det,
            device=device, verbose=False,
        )
    except Exception as exc:
        # GPU 间歇性不可用时降级到 CPU 重试（应对 device_count=0）
        if device not in (None, "cpu") and self._is_cuda_error(exc):
            import logging
            logging.getLogger(__name__).warning(
                "GPU 推理失败，降级到 CPU 重试：%s", exc
            )
            results = engine.predict(
                image, imgsz=imgsz, conf=conf, iou=iou, max_det=max_det,
                device="cpu", verbose=False,
            )
        else:
            raise
    # ... 后续 _parse / _draw 不变
```

新增 `_normalize_device` 和 `_is_cuda_error` 辅助方法：

```python
@staticmethod
def _normalize_device(device):
    """将 device 归一化为 ultralytics 可接受的值。
    - None / '' / 'auto' → None（ultralytics 自动选择：GPU 优先，无 GPU 则 CPU）
    - 'cuda:0' / 'cuda:1' 等 → 0 / 1（int，ultralytics 期望的格式）
    - 'cpu' → 'cpu'
    - '0' / 0 → 0
    """
    if device is None or device == "" or device == "auto":
        return None
    if isinstance(device, str) and device.startswith("cuda:"):
        try:
            return int(device.split(":")[1])
        except (IndexError, ValueError):
            return 0
    if isinstance(device, str) and device.isdigit():
        return int(device)
    return device

@staticmethod
def _is_cuda_error(exc):
    """判断异常是否与 CUDA 不可用相关（用于决定是否降级到 CPU）。"""
    msg = str(exc).lower()
    return any(k in msg for k in ("cuda", "device", "gpu"))
```

**为什么**：这是最关键的修复点。归一化确保即使前端/models.yaml 传 'auto' 或 'cuda:0'，
后端也能正确处理为 ultralytics 期望的 `None`/`0`。CPU 降级应对 CUDA 间歇性不可用。

## 四、假设与决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| device 归一化放哪层 | 后端 detector.py（`_normalize_device`） | 单点修复，覆盖所有入口（API params / models.yaml / 动态注册），前端无需严格校验 |
| models.yaml 用 null 还是 0 | `null`（None） | ultralytics None = 自动选择（GPU 优先 + CPU 降级），比硬编码 0 更健壮（应对 CUDA 间歇不可用） |
| 是否强制用 GPU | 否，device=None 自动选择 | CUDA device_count 间歇性为 0，强制 GPU 会偶发失败；None 能优雅降级 |
| 前端 'cuda:0' 改成什么 | `'0'`（字符串，后端归一化为 int 0） | ultralytics `select_device('0')` 或 `select_device(0)` 均有效，`'cuda:0'` 无效 |
| 测试图片来源 | 优先用用户 UAV 原图；无则合成图 | 需验证真实场景，但合成图可验证管线连通性 |
| 是否修改 counting_api | 否 | 计数走 `counter.count() → detector.detect()`，detector.py 修复后计数自动恢复 |
