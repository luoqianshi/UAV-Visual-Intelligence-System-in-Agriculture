## 一、最值得带走的五条

1. **Flask 单端口托管 SPA，不要同时启用内置 `static` 端点。** 内置端点会抢占 `/<path>`，导致 `/algo/models` 等前端路由刷新 404；正确做法是关闭 `static_folder/static_url_path`，用一个 `serve_spa` 同时处理真实文件、SPA 回退和未匹配 `/api` 的 JSON 404，并为它写回归测试（[app.py:30-33](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/app.py#L30-L33)、[app.py:67-82](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/app.py#L67-L82)、[test_api_wiring.py:121-146](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/tests/test_api_wiring.py#L121-L146)）。
2. **跨层数据契约必须显式，颜色空间是第一优先级。** 同一张图，检测工作台 14 个检出，计数工作台只有 2 个：计数链路把 `cv2.imread` 的 BGR 转成 RGB ndarray 再交给按 BGR 处理的 ultralytics，模型看到的是 R/B 反转图。修复不是“改一行 cvtColor”，而是把 `clahe/counter/detector/绘制/编码` 全链路统一为 BGR 并在模块边界写死约定（[clahe.py:1-16](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/clahe.py#L1-L16)、[counter.py:42-47](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/counter.py#L42-L47)、[detector.py:178-203](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/detector.py#L178-L203)、[bug 006:14-68](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/.lqs/bug_report/006_20260811_092632_计数工作台颜色通道反转致检测失准.md#L14-L68)）。
3. **执行与状态分离，但只保证单进程。** 处理任务把 YAML registry 当唯一状态源，`TaskManager` 只负责跑；检测/计数却把任务状态放在内存，重启即丢。两者混用会让“轮询”在单进程下正常、多 worker/重启后 404（[processing_api.py:95-133](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/api/processing_api.py#L95-L133)、[task_manager.py:6-33](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/task_manager.py#L6-L33)）。
4. **文件系统当数据库，必须配三件套：幂等 ID、相对路径、软删除 + 忽略清单。** 自动扫描用文件夹名生成稳定 `batch_id`，手工登记用时间戳保证唯一，删除只删登记并把文件夹加入 `ignored_folders`；否则重启扫描会把用户删掉的批次全部“复活”（[batch_registry.py:86-107](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/batch_registry.py#L86-L107)、[batch_registry.py:283-297](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/batch_registry.py#L283-L297)）。
5. **测试和文档不会自动保持正确，必须有门禁或生成机制。** 本轮 `pytest` 结果是 **121 passed / 10 failed**，失败不是新 bug：9 个是 `ModelRegistry` 构造签名变更后测试没改，1 个是模型数 4→11 的硬编码断言；README 仍写“数据集 mock、6 个模型、103 项测试”。没有后端 CI，只有前端 Pages 构建（[test_api_wiring.py:62](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/tests/test_api_wiring.py#L62)、[test_registry.py:193](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/tests/test_registry.py#L193)、[deploy-frontend.yml](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/.github/workflows/deploy-frontend.yml)）。

## 三、API 契约与错误处理

统一信封 + axios 拦截器解包（`success:false` 转 reject）是全项目最稳的约定（[client.ts:9-25](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/frontend/src/api/client.ts#L9-L25)）；但信封统一不等于契约统一。

| 经验 | 场景 → 问题/代价 → 解法 | 可迁移性 / 前提 |
|---|---|---|
| 信封 + 拦截器 | 每个视图重复判断 `success` 会漏。拦截器集中解包，业务代码干净；代价是 axios 的 `AxiosResponse` 类型被“谎报”成 `{data:X}`，且图片/文件下载等非信封响应必须绕开 axios。[client.ts:4-25](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/frontend/src/api/client.ts#L4-L25) | 高；前提是团队接受“200 业务信封”而非严格 REST |
| HTTP 状态码要统一 | batches/datasets/processing 用 400/404/503，models/detect/counting 失败也返回 200；前端拦截器能兜住，但 curl、监控、网关无法按状态码区分。测试甚至把“未知模型返回 200”固化成了断言。[models_api.py:65-76](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/api/models_api.py#L65-L76)、[batches_api.py:46-49](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/api/batches_api.py#L46-L49)、[test_api_wiring.py:86-94](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/tests/test_api_wiring.py#L86-L94) | 中；一旦有外部调用方就必须统一 |
| 任务错误语义别复用 `error` 键 | `TaskManager.get()` 对“不存在”返回 `{"error":"任务不存在"}`；而失败任务也把异常写进 `error`。API 用 `if task.get("error")` 判断，导致“任务已失败”被当成 404 不存在。[task_manager.py:32-33](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/task_manager.py#L32-L33)、[detect_api.py:171-176](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/api/detect_api.py#L171-L176) | 高；任何异步任务接口都该用 `status` + 独立 `not_found` 语义 |
| 异步状态要持久化 | 检测/计数任务只在内存，重启后轮询 404；处理任务用 YAML + `index.json` 可恢复。同一个系统两套生命周期，用户无法预期。[processing_registry.py:38-56](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/processing_registry.py#L38-L56) | 高；长任务要么持久化，要么明确“重启即丢” |
| 返回提交前快照 | 异步 worker 会立刻改写共享 `cfg` 的 `status`；API 先 `dict(cfg)` 再投递，避免响应体在序列化时被 worker 改脏。这是共享可变状态下的低成本防线。[processing_api.py:61-62](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/api/processing_api.py#L61-L62) | 高；所有“提交后立刻返回”的异步接口都适用 |
| 路径与 MIME | 预览端点用 `folder / filename` 拼路径，未做 `resolve()` 前缀校验；实测 `C:/Windows/win.ini` 可经 `size=original` 读出（200/image/jpeg/92B）。原图也一律标 `image/jpeg`，PNG/TIFF 会坏。[batches_api.py:140-158](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/api/batches_api.py#L140-L158)、[batch_registry.py:354-367](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/batch_registry.py#L354-L367) | 高；本地可信环境可接受，暴露到网络前必须修 |

## 四、领域数据与持久化

模型、架次、处理任务、数据集四类元数据全部走 YAML 注册中心，没有数据库。这个选择让“把文件夹拷进 `data/` 就自动出现”成为可能，也把一致性责任全部推给了应用层。

| 经验 | 场景 → 问题/代价 → 解法 | 可迁移性 / 前提 |
|---|---|---|
| YAML + 启动自扫描 | 用户不想手写数据库。启动扫 `data/` 一级目录、按 `{crop}_{date}_{altitude}m` 推断元数据，未注册且未忽略的自动登记；已有登记只重建内存图片索引。[batch_registry.py:65-125](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/batch_registry.py#L65-L125)、[batch_registry.py:445-472](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/batch_registry.py#L445-L472) | 中；适合单机、数据量 < 数千、无并发写；不适合多用户/审计 |
| ID 生成规则 | 不同来源需要不同幂等性：自动扫描要“同一文件夹永远同一 ID”，手工登记要“同名也能区分”，处理任务要“按时间可排序”，结果要“绝不撞车”。混用会导致重跑/覆盖/排序错乱。 | 高；见下表 |
| 相对路径优先 | 存相对 `PROJECT_ROOT` 路径，搬项目仍可用；外部盘只能存绝对路径。实际 `batches.yaml` 有 6 条 `D:/.../RGB`，换机即失效，且 YAML 被 gitignore。[batch_registry.py:474-489](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/batch_registry.py#L474-L489)、[batches.yaml:59](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/data/batches.yaml#L59) | 中；外部路径要配“失联”状态与重定位 |
| 软删除 + 忽略清单 | 删除登记不删原图，避免误删几个 GB 的航拍数据；自动发现的文件夹删除后加入 `ignored_folders`，防止下次启动复活。代价是按“文件夹名”而非完整路径记录，同名目录会互相误伤。[batch_registry.py:283-297](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/batch_registry.py#L283-L297) | 中；仅适用于“文件是主人、登记是视图”的本地工具 |
| YAML 写入安全 | 所有 `save_to_yaml()` 都是 `open(...,"w")` 直接覆盖，没有临时文件 + `os.replace`、没有锁、没有备份；写一半崩溃会得到截断 YAML。当前靠“单进程 + 低并发”侥幸。[batch_registry.py:126-142](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/batch_registry.py#L126-L142)、[processing_registry.py:58-70](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/processing_registry.py#L58-L70) | 高；只要元数据值钱，就必须原子写 |

**ID 方案对照（真实代码）**

| 对象 | 规则 | 解决的问题 | 代价 |
|---|---|---|---|
| 自动架次 | `batch_{sanitized_folder}` | 同一文件夹重复扫描幂等 | 文件夹改名 = 新批次，旧登记可能变孤儿 |
| 手工架次 | `batch_{name}_{HHMMSS}` + 冲突循环 | 同名可区分 | 依赖时钟；不可读性一般 |
| 处理任务 | `{type}_{YYYYmmdd_HHMMSS}_{ms:03d}` | 可按时间排序、目录名=task_id、可反查 | 同毫秒冲突靠循环 +1ms |
| 计数结果 | `count_{ts}_{uuid6}` | 绝不撞车 | 不可排序、不可读 |
| 内存任务 | `{type}_{ts}_{uuid6}` | 进程内唯一 | 重启即丢 |

## 五、批处理与失败隔离

数据处理的真实价值不在 CLAHE 本身，而在“把 80 张 4–8MB 原图稳定变成 5,040 张 tile，并且失败可解释”。当前实现做到了“不中断”，还没做到“可解释”。

| 经验 | 场景 → 问题/代价 → 解法 | 可迁移性 / 前提 |
|---|---|---|
| 单图错误隔离 | 一张坏图不能让整批 5,000 张白跑。`run_clahe/run_crop` 对每张图 `try/except`，只 `logger.warning` 并继续；任务最终用 `processed_images/total_images` 体现损失。[processing_engine.py:46-64](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/processing_engine.py#L46-L64) | 高；但必须补错误清单，见隐患表 |
| `index.json` 作为产物自描述 | YAML 丢了也能从 `output/{task_id}/index.json` 重建任务；下一任务可把该目录当输入，按 `sub_dirs` 精确定位，不必递归猜目录。实际已出现 `crop → clahe` 链式任务（5,041 文件/1.25GB）。[processing_engine.py:130-145](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/processing_engine.py#L130-L145)、[processing_registry.py:198-244](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/processing_registry.py#L198-L244) | 高；任何“产物还要继续被消费”的管线都该写 manifest |
| 批推理 + 触顶显性化 | 逐块 `predict` 浪费 GPU；改为 `detect_batch(images, batch=batch_size)`，失败回退批内串行。`max_det` 触顶会静默丢框，因此返回 `max_det_reached_tiles`，前端给“调大 max_det 或调小 tile_size”告警。[detector.py:66-114](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/detector.py#L66-L114)、[counter.py:83-103](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/counter.py#L83-L103) | 高；密植/小目标计数必用 |
| GPU 失败降级 | `device='auto'`/`'cuda:0'` 在 ultralytics 8.4.60 中无效；CUDA `device_count` 还会间歇为 0。后端单点 `_normalize_device()` 把 auto→None、cuda:0→0，并在 CUDA 异常时用 CPU 重试。[detector.py:132-159](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/detector.py#L132-L159)、[bug 003:40-99](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/.lqs/bug_report/003_20260809_201100_检测推理device无效值修复.md#L40-L99) | 高；所有 GPU 可选任务都适用 |
| 进度回调的写放大 | `on_progress` 每处理一张图就 `registry.update_task()`，而后者每次都整文件重写 YAML。80 图任务尚可，5,040 图任务就是 5,040 次全量写；叠加 `max_workers=1` 的串行执行，进度更新本身成为 I/O 热点。[processing_api.py:103-107](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/api/processing_api.py#L103-L107)、[processing_registry.py:116-125](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/processing_registry.py#L116-L125) | 中；应节流（按 % 或 1–2s）并原子写 |

## 十、适用边界与复用清单

**适用边界**：适合单机/单用户科研工具——文件夹为主、元数据量小、任务串行、Windows + conda、演示优先；不适合多用户/审计、多 worker/容器、万级条目或外网开放。总体是以“零外部服务”换并发、审计与扩展性。

**迁移到新项目时的最小清单**：

1. 先定“单一入口 + 静态托管”边界，并写 SPA 回退/未知 API 回归测试。
2. 把可选重依赖全部延迟导入，`init_engines()` 按模块独立降级，health 暴露真实就绪状态。
3. 选一个持久化真源（YAML/SQLite），所有写走 `临时文件 + os.replace`，并明确单进程/多进程。
4. 为每个领域定 ID 规则：幂等、唯一、可排序分别用不同方案，不混用。
5. 文件扫描与输入计数抽成同一函数；单条失败写 `errors[]`，设失败率阈值。
6. 跨层数组/图像契约写死颜色空间与形状，关键链路加“黄金图”回归。
7. 异步任务先落库再执行；响应返回提交前快照；失败与不存在用不同状态。
8. 前端分页 + 懒加载 + 缩略图；图表在容器挂载后渲染；轮询有清理和重试。
9. CI 跑 `pytest` + `vue-tsc`；README 的模型数/测试数/模块状态由脚本生成。
10. 对外暴露前关 debug、绑 127.0.0.1、加认证、校验预览路径与上传。
